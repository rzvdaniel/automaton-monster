# AGENTS.md

This repository is the [automaton.monster](https://automaton.monster) store: showcase apps, games and experiments for [Automaton](https://github.com/rzvdaniel/automaton). It is an optional catalog source; the essential apps stay in the official catalog, [automaton-apps](https://github.com/rzvdaniel/automaton-apps). Each app is one folder with its own `automaton.json`, source and tests; there is no shared build.

- `analytics/`, `games/`, `productivity/`, `wallpapers/`: one folder per app.
- `design/automaton-app-ui/`: a copy of the UI kit from automaton-apps (the kit is maintained there; keep the copy identical).
- `tools/`: the catalog generator and CI checks (the same as in automaton-apps). `catalog.json` is generated by CI; never edit it.
- `catalog-apps.json`: lists the apps in the catalog (category and oldest server version). An app that used to be in the official catalog carries `movedFrom` (repo and folder), so servers that installed it there keep updating it from here. Never remove a `movedFrom`.

Agent workflow skills in `.agents/skills/`: `apps-write-issue`, `apps-write-pr`, `apps-ship-app` (issue to installed app), `apps-orchestrate`.

**Before building or changing any app UI, read [`.agents/skills/automaton-app-design/SKILL.md`](.agents/skills/automaton-app-design/SKILL.md).**

## Add an app

1. Create `<category>/<app>/` with `automaton.json` (a `name` and `summary` are required), source, tests and a `README.md`. Copy the shape of an existing app.
2. If it has a page, vendor the UI kit into its `ui/` folder (see the skill).
3. Add the folder to `catalog-apps.json` and the app to the table in `README.md`.
4. Add a `test.sh` to the app folder (run from that folder; exit non-zero on failure). The shared `App tests` workflow runs it for changed apps; do not add a per-app workflow.

## CI

`Catalog` runs the tool tests, `python tools/validate_apps.py` (the server's own `automaton validate` contract check on changed apps; needs the CLI), `python tools/check_vendored_ui.py` and `python tools/generate_catalog.py --validate`. `App tests` runs each changed app's `test.sh` (`tools/run_app_tests.py`), `Checks` runs `tools/check_manifests.py`, the pin check and the gate's tests, and `Merge gate`, `CodeQL` and `Dependency review` guard every pull request (tiers in `.github/CODEOWNERS`, logic in `.agents/tools/merge-gate.py`). Run the same commands locally before opening a pull request. The first `catalog.json` is written by CI after the first merge.
